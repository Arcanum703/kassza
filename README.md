# Kassza

**A private receipt and bank-statement ledger built on Gemma 4.** Photograph a Hungarian receipt and get a ledger row with the VAT split, checked by code. Import a bank CSV and get advice on what to cut next month, where every number is checked against your own data. Flip one switch and it runs fully offline on your laptop, so your financial life never leaves your machine.

Built at Hacktoberfest Hack Day Budapest, 31 Oct 2026. MIT licence.

## Why this isn't "just paste it into a chatbot"

| A chatbot | Kassza |
|---|---|
| Reads the receipt, and you hope the numbers are right | Code checks that the items add up to the total, VAT codes are valid, the VAT summary matches, and the date and tax number are well-formed. On failure, Gemma is shown the exact errors and re-reads the photo. |
| Does arithmetic in its head | Net and VAT are computed by code. Bank amounts are parsed by code. Gemma only reads text and names categories. |
| Gives advice that can quote made-up figures | Code computes a numbered fact sheet from your ledger. Gemma may only quote numbers from it. A checker rejects any suggestion with a number that isn't in your data, and the UI shows it as rejected. |
| Sends your receipts and bank history to a cloud | **Private mode** runs `gemma4:e4b` through Ollama on your machine. That's only possible because Gemma's weights are open. |

## How it uses Gemma 4

- **Multimodal:** a receipt photo goes straight to JSON (vendor, tax number, line items with VAT letters, VAT summary, rounding, total, category).
- **Multilingual:** item names stay in Hungarian; categories and advice come out in English.
- **Two sizes, one interface:** `gemma-4-31b-it` through the Gemini API, or `gemma4:e4b` on-device. Switch backends live from the header.
- **Self-correction loop:** a failed check becomes a targeted retry prompt.

## Run it

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows; use source .venv/bin/activate elsewhere
pip install -r requirements.txt
cp .env.example .env              # add GEMINI_API_KEY for cloud mode
python app.py                     # http://localhost:8000
```

**Private mode:** install [Ollama](https://ollama.com), run `ollama pull gemma4:e4b`, then click **Private · on-device**.

**Stage safety net:** every model response is cached in `cache/`. Set `KASSZA_REPLAY=1` to serve only cached responses (no network, no rate limits).

```bash
pytest   # validator tests
```

## Add your country

Copy `countries/hu.json` and edit the VAT codes and rates, the cash-rounding step, the tax-number pattern, the receipt hints and the categories. Then set `KASSZA_COUNTRY=xx`. No code changes needed.

## Export

`/api/export.csv` writes `date, payee, category, amount`, which you can import into open-source budgeting apps such as Actual Budget or Firefly III.

## Layout

| File | What it does |
|---|---|
| `kassza/llm.py` | Gemini API and Ollama backends, response cache, replay mode |
| `kassza/receipt.py` | Photo → JSON → checks → one retry with errors |
| `kassza/validate.py` | The maths: totals, VAT split, codes, date, tax number |
| `kassza/bank.py` | CSV parsing (Revolut and generic), merchant categorisation |
| `kassza/insights.py` | Fact sheet by code, advice by Gemma, number grounding check |
| `app.py`, `static/index.html` | FastAPI and a single-page UI |

`samples/demo-bank.csv` is synthetic data generated by `scripts/make_demo_bank.py`.
